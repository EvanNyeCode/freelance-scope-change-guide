# Freelance change order example: add a reporting dashboard

This example shows how to make a scope change easy to compare before extra work begins. It is planning guidance, not legal advice or a contract.

## Original approved scope

A client approved a small marketing site for **$3,200** with:

- five responsive pages;
- copy and assets supplied by the client;
- two review rounds;
- delivery by June 28; and
- a handoff call after approval.

The approved scope did not include analytics dashboards, data integrations, or ongoing reporting.

## The new request

After the homepage was approved, the client asked for a reporting dashboard that combines analytics data, adds three filters, and refreshes weekly.

That request is reasonable, but it changes the deliverable, technical work, client inputs, and schedule. It should be priced before implementation.

## Calculate the added work

Use an illustrative estimate such as:

- dashboard build: **8 hours**;
- data setup and access coordination: **2 hours**;
- testing and handoff: **2 hours**;
- internal rate: **$100/hour**;
- schedule impact: **three working days** after the required analytics access is available.

The illustrative added price is **12 × $100 = $1,200**. Replace these figures with the actual effort, rate, agreement, and project constraints.

## Client-ready response

> Thanks for the dashboard request. The dashboard and weekly refresh are outside the approved five-page site scope, which does not include analytics integrations or reporting. I can add the dashboard for **$1,200**, with delivery moving by three working days after analytics access is available. That includes the dashboard, three filters, one test pass, and the handoff call. Or we can keep the approved site scope and schedule the dashboard as a follow-on phase. Please confirm which option you prefer before I begin the added work.

## What to record

Keep the original scope visible, then record:

1. the requested dashboard and what is excluded;
2. the assumptions about analytics access and data quality;
3. the added effort and price;
4. the revised delivery date;
5. the included review or test limit; and
6. the written approval before work starts.

If the client changes the request again, compare the new request with this approved change rather than silently absorbing it into the original price.

## Quick check

- Is the new deliverable named?
- Are access and data assumptions explicit?
- Is the added price tied to estimated effort?
- Is the schedule impact visible?
- Is the original scope still an option?
- Is written approval required before implementation?
